# LLM Fine-Tuning Analysis

## 1. Decision
**DO NOT FINE-TUNE FOR MVP.**

## 2. Rationale
The chosen model, `Qwen/Qwen3-4B-Instruct` (via Ollama, 4-bit GGUF), possesses strong zero-shot multilingual reasoning. Fine-tuning an LLM requires significant computational resources, curating thousands of high-quality conversational turns, and risks catastrophic forgetting of the model's base language capabilities.

## 3. The RAG + Prompting Strategy
Instead of baking scheme knowledge into model weights via fine-tuning, knowledge will be injected at runtime:
1. **RAG Pipeline:** Retrieve exact scheme details from ChromaDB.
2. **Structured Prompting:** Provide the LLM with a strict system prompt instructing it to answer ONLY based on the provided context.
3. **Eligibility Engine:** Use Python rules to calculate age/income eligibility and pass the boolean results to the LLM, preventing the LLM from attempting (and failing) complex arithmetic reasoning.

### Example Prompt Architecture:
```text
[System] You are an assistant for Tamil Nadu Government Schemes. Answer the user strictly based on the following context. If the answer is not in the context, say "I do not have this information."

[Context]
Scheme: Kalaignar Magalir Urimai Thogai
Amount: Rs. 1000/month
Eligibility: Women head of family, Annual income < Rs. 2.5 lakhs.

[User Query] Who is eligible for the 1000 rupees scheme?
```

## 4. Hardware Constraints
- **Target:** 8-16GB RAM student laptop (No GPU).
- Fine-tuning even a 4B model via QLoRA requires >12GB VRAM (GPU).
- **Cost:** ₹0.

## 5. Risks and Fallback
- **Risks:** Hallucination of scheme amounts or deadlines if the RAG context is ignored.
- **Fallback:** Post-processing regex checks to ensure any numbers generated by the LLM exist in the source context.
- **Future Path:** If benchmarks (Factuality/Hallucination rates) show severe issues, curate an instruction-tuning dataset and fine-tune via QLoRA on a cloud GPU.
